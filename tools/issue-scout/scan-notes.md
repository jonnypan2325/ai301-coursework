# issue-scout scan notes

Dated log of what each scan got wrong and what changed because of it.

- 2026-11-11 (scan 1): all three rejections (welfare-time#100, repowise#5478, pycord#3437) ranked in the 1-5 comment band and the single comment on each was a same-day claim. Ranking filter 5 had put 1-5 comments ahead of 0 on the theory that a comment meant an engaged maintainer. Changed search-strategy.md filter 5 to order fewest comments first (0, then 1-5, then 6-10).
- 2026-11-11 (scan 1): Q3 (Python `llm agent` bugs) never reached the top 5. Its results carry no good-first-issue label and lost every ordering tie to Q1/Q2, so the agentic half of the fit profile never got graded. Named the queries Q1-Q3 in search-strategy.md and added ranking filter 7, which reserves the fifth grading slot for the best surviving Q3 result.
- 2026-11-11 (scan 1): the AI-assisted contribution check passed pycord#3437 although its CONTRIBUTING.md says AI use by new contributors is "highly discouraged, and will likely result in the direct closure". The scout passed it by the letter (not an explicit ban) and flagged the tension itself. Added a fail condition to that check in rubric.md for newcomer AI warnings that threaten closure, and kept warnings tied only to breaking a stated condition (such as undisclosed AI use) as passes.
- 2026-11-11 (grade 1): Xplore-workshop#27 passed the bounded-scope check although it is a Python homework exercise: the repo's CONTRIBUTING.md sends each student's answers to `SOLUTIONS/<githubid>_solutions/` and says not to touch the originals, so no fix ever closes the issue. It was rejected anyway on Maintainer alive, so the gap did not change a verdict this time. Added a fail condition to Bounded non-breaking scope in rubric.md for course, workshop, or tutorial exercises that no single fix can close.
- 2026-11-11 (grade 1): AntAlmanac#2101 was accepted with no warning that the repo requires a maintainer to assign an issue before work starts and keeps some tasks for its own team. The issue was opened by a team member a day earlier and carries no good-first-task label, so a claim may be declined. The scout caught this only in its free-text notes. Added a preferred check, Open to outside claim, to rubric.md: it fails assign-first or team-reserved repos when the issue has no newcomer label, and makes the summary say so. It is preferred, not required, because waiting for assignment is a normal, workable rule.
- 2026-11-17 (Unit 6 scope patch): replaced the Bounded non-breaking scope check in rubric.md with the staff scope-feasible row and added the difficulty note section under the checks table. The old row rejected issues for any unsettled product decision; that now raises the difficulty note instead. Kept two fail conditions from the old row because they are not open edges: the course-exercise fail added 2026-11-11 (Xplore-workshop#27) and the explicit breaking-change fail from my fit profile.
